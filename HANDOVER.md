## 3. CI Pipeline & Build Notes

### GitHub Actions Workflow (`.github/workflows/ci.yml`)
- **Job 1 (`Core & Platform Unit Tests (Linux)` on `ubuntu-latest`):**
  - Compiles and runs `make HV_TLB_PAGE_BITS=12 test-core hvsparse` and `make HV_TLB_PAGE_BITS=14 test-core hvsparse` with `-Wall -Wextra -Werror`.
  - Runs a binary pack/unpack round-trip check (`cmp build/raw.bin build/unpacked.bin`).
  - Runs `python3 -m py_compile`, `bash -n`, and `bash scripts/provision_archlinux_arm64.sh --dry-run`.
- **Job 2 (`iOS Unsigned IPA Build (macOS)` on `macos-latest`):**
  - Selects Xcode 26 (`Xcode_26.6.app`), installs `xcodegen`, `meson`, `ninja`, and `pkg-config`, runs `bash scripts/sync_upstream.sh`, restores/caches `.upstream/WindowsiOS/ios/deps` (`libffi`, `glib`, `libslirp`, `libintl`, `libpcre2-8`), builds `make test-core hvsparse ios-lib` (`build/ios/libhengelinux.a` with full `HengeVM` engine linked), generates `ios/HengeLinux.xcodeproj`, runs `xcodebuild -sdk iphoneos CODE_SIGNING_ALLOWED=NO build`, packages `build/HengeLinux-unsigned.ipa` + `.sha256`, uploads the Actions artifact (`HengeLinux-unsigned-ipa`), and updates the rolling **`latest-ipa` GitHub Pre-Release** (`https://github.com/venim1103/henge-linux/releases/tag/latest-ipa`).
  - **Sideloading from Linux, Windows, or Intel Mac:** Download [`HengeLinux-unsigned.ipa`](https://github.com/venim1103/henge-linux/releases/download/latest-ipa/HengeLinux-unsigned.ipa) directly on your iPhone/iPad and sign/install it with **SideStore** or **AltStore**—no local Mac required.

### Resolved SDK / Toolchain Issues (Do Not Reintroduce)
1. **iPhoneOS SDK `<mach/mach_vm.h>`:** Public `iPhoneOS.sdk` headers fail compilation with `#error mach_vm.h unsupported.` Always use `<mach/mach.h>` instead.
2. **macOS `_POSIX_C_SOURCE`:** Defining `_POSIX_C_SOURCE` on `__APPLE__` hides BSD `u_int`/`u_char`/`u_short` types required by `<sys/sysctl.h>` and `MAP_ANON`. Gate `_POSIX_C_SOURCE` with `#if !defined(__APPLE__)`.
3. **XcodeGen `Info.plist` & Entitlements `properties:`:** Keep `GENERATE_INFOPLIST_FILE: YES` on `HengeLinux` and always define explicit `properties:` blocks under `info:` (`HengeLinuxJITExtension`) and `entitlements:` (`HengeLinux`) alongside `MARKETING_VERSION` + `CURRENT_PROJECT_VERSION` in `ios/project.yml`, otherwise `xcodegen generate` overwrites `Info.plist` without `NSExtension` (causing SideStore `IXErrorDomain Code=17`) and wipes `HengeLinux.entitlements`.
4. **`CAMetalLayer` Ownership & `fb_metal.m` Lock Order:** Host the guest display in `MetalDisplaySurfaceView` (`layerClass = CAMetalLayer.self`), never an unpaused `MTKView` (which steals drawables via its own 60 Hz `CADisplayLink`). In `fb_metal.m`, wrap `(void)tick` via method renaming to `_hengeUnlockedTick` so `hengelinux_render_lock()` is always acquired *outside* `os_unfair_lock` and released on every return path.
5. **SFSafariViewController & `xdg-open` URL Scheme Guard:** `SFSafariViewController(url:)` throws an uncatchable `NSInvalidArgumentException` for non-HTTP(S) schemes; enforce `http`/`https` + non-empty host in `HengeVMBridge.mm` / `HengeLinuxApp.swift` and delegate non-HTTP(S) URIs/files in `guest/henge-xdg-open` to `/usr/bin/xdg-open`.
6. **ObjC++ (`HengeVMBridge.mm`) C Header Linkage:** Upstream `winvm.h` and `share.h` omit `extern "C"`; always wrap them inside `extern "C" { ... }` when including from `.mm` files so linker symbols do not get C++-mangled.
7. **Darwin Clang `.S` Preprocessor & `AudioToolbox.framework` Linker Order:** Darwin's `.S` driver does not expand C preprocessor token-pasted `_##name` labels (keep explicit `.globl _henge_jit26_*` blocks in `host/henge_brk.S`), and `ld` resolves `.tbd` framework stubs in `HengeLinux-linker-args.resp` *before* `OTHER_LDFLAGS` (`-lhengelinux`), so `-framework` / `AudioToolbox` must appear *after* `-lhengelinux` in `ios/project.yml` `OTHER_LDFLAGS` to resolve `up_host_audio_mac.o` symbols.
8. **iOS `Files.app` Container Visibility & StikDebug Per-App Script Binding:** iOS `LocalStorage` FileProvider requires `CFBundleDocumentTypes` + `UTImportedTypeDeclarations` alongside `UIFileSharingEnabled` and `LSSupportsOpeningDocumentsInPlace` in `ios/project.yml` (verified by `.github/workflows/ci.yml`), and LaunchServices caches container visibility across in-place SideStore refreshes until the app is reinstalled. In **StikDebug**, users must place `henge-jit.js` in `On My iPhone ▸ StikDebug` and **long-press `HengeLinux` -> `Assign Script` -> `henge-jit.js`** (starring `henge-jit.js` as default does not bind it to a specific app).

## 5. Full-Repository 42-File Deep Audit & Physical-Device Boot Log Findings (Post-Milestone 5.6 / Commit `7628e20`)

A complete 5-batch audit across all 42 repository files plus physical iPhone boot telemetry (`2024.02-2ubuntu0.10` EDK2 UEFI + `ramfb 800x600` + `Blessed 384 MiB @ 0x100b7c000`) identified the root cause of the TianoCore `Start boot option` boot stall and cataloged 28 prioritized remediation items (`P1`–`P3`) for the next engineering pass.

### 5.1 On-Device Boot Log Diagnosis & Telemetry Findings
1. **Verified Working on Physical iPhone Hardware:** TXM dual-mapped JIT (`Blessed 384 MiB @ 0x100b7c000`), vCPU startup, EDK2 ArmVirtQemu UEFI firmware (`2024.02-2ubuntu0.10`), and `ramfb` (`800x600`) initialize cleanly, then UEFI `BdsDxe` stops at `Start boot option` with zero `EFI stub:` or `systemd-boot` output on `ttyAMA0`.
2. **Root Cause #1 — `objcopy` UKI PE/COFF Header Rejection vs. Native `systemd-bootaa64.efi` (`scripts/build_prebuilt_archlinux_arm64.sh:250-305`):**
   - Constructing `EFI/BOOT/BOOTAA64.EFI` by running `objcopy --add-section` on Ubuntu 24.04's `/usr/lib/systemd/boot/efi/linuxaa64.efi.stub` without updating PE/COFF optional header `SizeOfImage`, `SizeOfInitializedData`, and `.reloc` entries produces an EFI binary that strict EDK2 `LoadImage()` can reject with `EFI_LOAD_ERROR` / `EFI_SECURITY_VIOLATION`, dropping silently to the TianoCore menu.
   - **Fix:** Install Arch Linux ARM's native `systemd-bootaa64.efi` (`$MNT_DIR/usr/lib/systemd/boot/efi/systemd-bootaa64.efi`) as `EFI/BOOT/BOOTAA64.EFI` (which natively parses the existing `loader/loader.conf` and `loader/entries/arch.conf` without PE header surgery), falling back to direct `CONFIG_EFI_STUB` `/boot/Image` + `startup.nsh` (`\Image initrd=\initramfs-linux.img ...`).
3. **Root Cause #2 — QEMU `VERIFY_BOOT=1` Device Tree vs. HengeVM ACPI 6.3 Mismatch (`scripts/build_prebuilt_archlinux_arm64.sh:436-438`):**
   - `VERIFY_BOOT=1` invokes `qemu-system-aarch64 -machine virt,gic-version=3` *without* `acpi=on`, testing Device Tree boot in CI whereas `HengeVM` emulates an **ACPI 6.3** motherboard (`-machine virt,gic-version=3,acpi=on`).
   - **Fix:** Pass `-machine virt,gic-version=3,acpi=on` to `qemu-system-aarch64` in `VERIFY_BOOT=1` so CI validates the exact ACPI 6.3 boot path used on iOS.
4. **Immediate UEFI Shell Workaround on Existing Images:**
   - Before rebuilding `archlinux.hvsparse`, tapping **Esc** during the TianoCore splash -> **Boot Manager -> EFI Internal Shell** and executing `fs0:\Image root=UUID=<ROOT_UUID> rw rootwait console=tty0 console=ttyAMA0,115200` bypasses the UKI stub and boots `/Image` directly via Linux's built-in `CONFIG_EFI_STUB`.
5. **Secondary Telemetry Note (`standard ledger` vs. `LEDGER_NO_FOOTPRINT`):**
   - Even when `CS_DEBUGGED=YES` (`cs_debugged=1`) persists after debugger detach, `mach_memory_entry_ownership(..., VM_LEDGER_FLAG_NO_FOOTPRINT)` falls back to standard ledger (`2560 MiB · 2D GOP (standard ledger)`) on iOS 26+ when not actively `P_TRACED` because `VM_LEDGER_FLAG_NO_FOOTPRINT` requires `com.apple.private.memorystatus` when detached. `2,560 MiB` still fits safely within an 8 GB iPhone's Jetsam ceiling.
