### Resolved SDK / Toolchain Issues (Do Not Reintroduce)
1. **iPhoneOS SDK `<mach/mach_vm.h>`:** Public `iPhoneOS.sdk` headers fail compilation with `#error mach_vm.h unsupported.` Always use `<mach/mach.h>` instead.
2. **macOS `_POSIX_C_SOURCE`:** Defining `_POSIX_C_SOURCE` on `__APPLE__` hides BSD `u_int`/`u_char`/`u_short` types required by `<sys/sysctl.h>` and `MAP_ANON`. Gate `_POSIX_C_SOURCE` with `#if !defined(__APPLE__)`.
3. **XcodeGen `Info.plist` & Entitlements `properties:`:** Keep `GENERATE_INFOPLIST_FILE: YES` on `HengeLinux` and always define explicit `properties:` blocks under `info:` (`HengeLinuxJITExtension`) and `entitlements:` (`HengeLinux`) alongside `MARKETING_VERSION` + `CURRENT_PROJECT_VERSION` in `ios/project.yml`, otherwise `xcodegen generate` overwrites `Info.plist` without `NSExtension` (causing SideStore `IXErrorDomain Code=17`) and wipes `HengeLinux.entitlements`.
4. **`CAMetalLayer` Ownership & `fb_metal.m` Lock Order / Full-Frame Hash:** Host the guest display in `MetalDisplaySurfaceView` (`layerClass = CAMetalLayer.self`), never an unpaused `MTKView` (which steals drawables via its own 60 Hz `CADisplayLink`). In `fb_metal.m`, wrap `(void)tick` via method renaming to `_hengeUnlockedTick` so `hengelinux_render_lock()` is always acquired *outside* `os_unfair_lock` and released on every return path, and hash every scanline/qword in `quick_frame_hash()` (upstream's `step_x = 6` qwords = 12 px skipped narrow 8 px console glyphs).
5. **SFSafariViewController & `xdg-open` URL Scheme Guard:** `SFSafariViewController(url:)` throws an uncatchable `NSInvalidArgumentException` for non-HTTP(S) schemes; enforce `http`/`https` + non-empty host in `HengeVMBridge.mm` / `HengeLinuxApp.swift` and delegate non-HTTP(S) URIs/files in `guest/henge-xdg-open` to `/usr/bin/xdg-open`.
6. **ObjC++ (`HengeVMBridge.mm`) C Header Linkage:** Upstream `winvm.h` and `share.h` omit `extern "C"`; always wrap them inside `extern "C" { ... }` when including from `.mm` files so linker symbols do not get C++-mangled.
7. **Darwin Clang `.S` Preprocessor & `AudioToolbox.framework` Linker Order:** Darwin's `.S` driver does not expand C preprocessor token-pasted `_##name` labels (keep explicit `.globl _henge_jit26_*` blocks in `host/henge_brk.S`), and `ld` resolves `.tbd` framework stubs in `HengeLinux-linker-args.resp` *before* `OTHER_LDFLAGS` (`-lhengelinux`), so `-framework` / `AudioToolbox` must appear *after* `-lhengelinux` in `ios/project.yml` `OTHER_LDFLAGS` to resolve `up_host_audio_mac.o` symbols.
8. **iOS `Files.app` Container Visibility & StikDebug Per-App Script Binding:** iOS `LocalStorage` FileProvider requires `CFBundleDocumentTypes` + `UTImportedTypeDeclarations` alongside `UIFileSharingEnabled` and `LSSupportsOpeningDocumentsInPlace` in `ios/project.yml` (verified by `.github/workflows/ci.yml`), and LaunchServices caches container visibility across in-place SideStore refreshes until the app is reinstalled. In **StikDebug**, users must place `henge-jit.js` in `On My iPhone ▸ StikDebug` and **long-press `HengeLinux` -> `Assign Script` -> `henge-jit.js`** (starring `henge-jit.js` as default does not bind it to a specific app).
9. **Darwin `COMMPAGE_TIMEBASE_OFFSET` (`0xfffffc088ull`), `core/dispatch.c` Timer Clock Domain & PL011 UEFI Input:** On Darwin/iOS, `mach_absolute_time()` equals `hardware_CNTVCT_EL0 + *(uint64_t *)COMMPAGE_TIMEBASE_OFFSET` (which subtracts all time the iPhone spent asleep before the VM launched). In `scripts/apply_upstream_patches.py`, `translate_counter()` (`core/translate.c`) must add **both** `COMMPAGE_TIMEBASE_OFFSET` and `*hengelinux_negative_counter_offset_ptr()`, and `core/dispatch.c` must compare `timer_due` / `next_due` against `hv_counter()` rather than raw `mach_absolute_time()`. Otherwise, inline guest `MRS CNTVCT_EL0` reads are billions of ticks ahead of `hv_timer_update()`, causing EDK2's 10 ms `ArmTimerDxe` timer interrupt (`WaitForEvent`) to never fire and freezing UEFI boot + input polling at `Start boot option`. Additionally, Ubuntu's `AAVMF_CODE.fd` polls PL011 UART (`0x09000000`) rather than xHCI USB during UEFI boot, so `HengeVMBridge.mm` forwards HID key presses to both `hv_winvm_key_hid()` and `hv_pl011_receive()`.

### Priority 0 (`P0`) — Physical-Device Sideload, TXM Blessing & Keyboard Blockers (Fix First)
1. **`ios/Sources/SelfDebugJITClient.swift` (lines 42, 126–133, 203 — SideStore / AltStore Bundle-ID Rewrite Breakage & XPC Timeout Skew):**
   - `extensionIdentifier` is hardcoded to `"io.hengelinux.app.jit-extension"` (line 42) and passed directly to `HengeJITExtensionBridge.invokeExtension(withIdentifier:...)` (line 203). When SideStore or AltStore signs `HengeLinux-unsigned.ipa` with a free Apple ID, it rewrites both the host bundle ID (`Bundle.main.bundleIdentifier`, e.g., `io.hengelinux.app.<TEAMID>`) and the embedded `.appex` bundle ID (`"\(bundleID).jit-extension"`), breaking `NSExtension(identifier:)` on 100% of SideStore/AltStore installs.
   - `workerAcquire` runs 40 attempts × `150 ms` (`6.0 s`, lines 127–131), which can expire before `xpcOutcome` (`timeoutSeconds: 6.5`, line 126) completes the debugserver handshake.
   - **Fix:** Derive `extensionIdentifier` dynamically from `Bundle.main.bundleIdentifier.map { "\($0).jit-extension" } ?? "io.hengelinux.app.jit-extension"` (with PlugInKit lookup fallback) and extend `workerAcquire` polling (`>= 16 s` / `110` attempts) to match a `15.0 s` XPC timeout.
2. **`ios/JITExtension/JITExtensionHandler.swift` (lines 309–318, 340–368 — 24,576 Sequential `M<addr>,1:69` TCP Round-Trips Exceed 8s XPC Timeout):**
   - For the default `384 MiB` JIT pool (`24,576` × `16 KiB` pages), lines 311–318 perform `24,576` sequential synchronous `send()`/`recv()` round-trips (`M<addr>,1:69`) without `TCP_NODELAY`. Over LocalDevVPN (`10.7.0.1`), `24,576` round-trips take ~7.5–29 s, hitting `HengeJITExtensionBridge.mm` timeout error `2005` (`8.0 s`).
   - **Fix:** Enable `TCP_NODELAY = 1` in `connectTCP()`, pipeline batches of 64–128 `M<addr>,1:69` frames per `send()` when `noAckMode == true` and drain matching `$OK#` replies, and bump `timeoutSeconds` to `15.0 s`.
3. **`host/henge_txm_jit.c` (lines 227–250 & 334–364 — `verify_rx_rw_selftest` Clobbers Byte-0 `0x69` Marker & Unchecked `VM_FLAGS_ANYWHERE`):**
   - `verify_rx_rw_selftest()` writes `kCode` (`0x52800540U`, LE byte 0 = `0x40`) at `offsets[0] = 0U` and `offsets[1] = bytes - HENGE_HOST_PAGE_SIZE`, overwriting the `0x69` TXM blessing marker at byte 0 of the first and last 16 KiB pages (breaking subsequent `henge_txm_verify_blessing_markers()` calls).
   - On the `VM_FLAGS_ANYWHERE` fallback (`lines 334–338`), `rw` is not checked for `(uintptr_t)rw != rx` or TXM bounds, and `vm_protect` failures (`lines 347–355`) omit `cur_prot`/`max_prot` diagnostics.
   - **Fix:** Write `kCode` at `off + 4U` (leaving byte-0 `0x69` markers intact), validate `(uintptr_t)rw != rx` after `vm_remap(..., VM_FLAGS_ANYWHERE)`, and include `cur_prot`/`max_prot` in `set_jit_status()` on `vm_protect` failure.
4. **`ios/Sources/SessionView.swift` (lines 389–402 — `insertText` Key-Down/Key-Up Same-Tick Collapse):**
   - `insertText(_:)` emits `sendHidKeyUsage(usage, pressed: true)` and `sendHidKeyUsage(usage, pressed: false)` in the same microsecond (lines 395–396), collapsing rapid keystrokes or duplicate characters before guest USB xHCI polling registers key-down state.
   - **Fix:** Route HID key events through a serialized async queue with ~12–15 ms key-down dwell spacing so xHCI latches every press and release.
5. **`guest/setup-arch-bridge.sh` (lines 17–20) + `guest/henge-xdg-open` (lines 345–349 — Confirmed Infinite `execv` Recursion Loop):**
   - `setup-arch-bridge.sh` lines 18–20 symlink `/usr/local/bin/xdg-open -> /usr/local/bin/henge-xdg-open` when `/usr/bin/xdg-open` exists (`[ -e /usr/bin/xdg-open ]`), and skip symlinking when `/usr/bin/xdg-open` is absent. When `henge-xdg-open` receives a non-HTTP(S) URI (`file://`, `mailto:`, local path), lines 346–347 invoke `os.execv("/usr/bin/xdg-open", ...)`; Arch's `/usr/bin/xdg-open` resolves `xdg-open` via `$PATH` (`/usr/local/bin/xdg-open` first) or `$BROWSER`, triggering an infinite `execv` loop.
   - **Fix:** In `guest/setup-arch-bridge.sh`, symlink `/usr/local/bin/xdg-open -> /usr/local/bin/henge-xdg-open` only when `/usr/bin/xdg-open` is *absent*, use `/etc/xdg/mimeapps.list` + `/etc/profile.d/henge-safari-bridge.sh` (`export BROWSER=/usr/local/bin/henge-xdg-open`) when `/usr/bin/xdg-open` is present, and set `HENGE_XDG_FALLBACK=1` (while stripping `henge-xdg-open` from `BROWSER`) in `guest/henge-xdg-open` before `os.execv("/usr/bin/xdg-open", ...)`.

### Priority 1 (`P1`) — Concurrency Races, UI Watchdog, Unwired VirGL Bus & State-Machine Bugs
6. **`host/henge_platform.c` (lines 358–379 & 298–317 — Multi-vCPU `CNTVCT_EL0` Jump Torn Read & Clock-Domain Mixing):**
   - In `hengelinux_compensated_counter()`, thread A can win the CAS on `g_last_raw_ticks` across a `> 500 ms` XNU freeze jump (line 363) while thread B sees `raw_ticks <= prev_raw` (line 360), exits the loop, and reads `g_suspend_offset_ticks` (line 376) *before* thread A runs `atomic_fetch_add` (line 370), spiking `g_last_compensated_ticks` forward by the entire sleep duration and freezing guest time.
   - `hengelinux_set_vm_clock_paused()` (lines 302, 306) samples `platform_raw_ticks_24mhz()` directly while `hengelinux_compensated_counter(raw_ticks)` takes caller-supplied `raw_ticks`; mixing synthetic unit-test ticks with wall-clock ticks corrupts `g_last_raw_ticks`, and `platform_raw_ticks_24mhz()` should check `mach_timebase_info` scaling on ARM64 Darwin rather than assuming 24 MHz unconditionally.
   - **Fix:** Synchronize `(g_last_raw_ticks, g_suspend_offset_ticks)` updates with a seqlock generation counter or `g_clock_mutex` on slow-path `> 500 ms` jumps, keep `hengelinux_set_vm_clock_paused()` aligned with `raw_ticks`, and verify `mach_timebase_info` scaling on ARM64 Darwin.
7. **`host/henge_virtio_gpu.c` (lines 35–41, 338–343, 384–397, 419–453 — Single-Owner `owner_ctx_id` Breaks Multi-Context VirGL Resources):**
   - `HengeGpuResourceSlot` stores a scalar `uint32_t owner_ctx_id` (line 37). When two Wayland VirGL contexts (client + compositor) attach the same resource via `CTX_ATTACH_RESOURCE`, the second attach overwrites `owner_ctx_id`, preventing `CTX_DETACH_RESOURCE` from decrementing the first context's `attached_resources`; duplicate attaches double-increment `attached_resources`; and `RESOURCE_UNREF` zeros the slot without decrementing attached contexts.
   - **Fix:** Replace `uint32_t owner_ctx_id` with a 32-bit `uint32_t attached_ctx_mask` bitmask (`1U << slot_idx`, matching `HENGE_VIRTIO_GPU_MAX_CONTEXTS == 32`) with idempotent bit set/clear on `CTX_ATTACH_RESOURCE`, `CTX_DETACH_RESOURCE`, `CTX_DESTROY`, and `RESOURCE_UNREF`.
8. **`ios/Sources/HengeVMBridge.mm` (lines 161–167, 299–312, 336–342) & `ios/Sources/HengeLinuxApp.swift` (lines 158–162 — `_gpuDevice` Not Wired into Live `HvWinVmConfig` / PCIe Bus):**
   - `startGuestWithRamMiB:` creates `_gpuDevice = henge_virtio_gpu_create(&_gpuConfig)` (line 166) and sets `_statusText` to `"Running · ... · VirGL 3D"` (lines 336–342), but neither `_gpuDevice` nor `gpuBackend` is passed into `HvWinVmConfig` or registered on upstream `devices/pcie.c` (`0x1af4:0x1050`), so the Arch Linux guest only sees 2D UEFI GOP (`simpledrm`/`efifb`).
   - **Fix:** Surface accurate UI/status labeling (`"2D GOP (VirGL 3D staged)"` until PCIe `0x1af4:0x1050` MMIO/virtqueue routing + `libvirglrenderer.a`/`ANGLE` are wired into `devices/pcie.c` and `winvm.c`).
9. **`ios/Sources/HengeVMBridge.mm` (lines 201–232) & `ios/Sources/HengeLinuxApp.swift` (lines 184–200 — Synchronous First-Boot `hv_sparse_unpack` Blocks `@MainActor` Watchdog):**
   - `HengeVMBridge` is `@MainActor` (`NS_SWIFT_UI_ACTOR`), and the Boot button calls `HengeVMBridge.shared.startGuest(...)` synchronously on `@MainActor`, running multi-GB `hv_sparse_unpack()` on the main thread and risking SpringBoard `0x8badf00d` watchdog termination.
   - **Fix:** Offload `hv_sparse_unpack()` into a background `Task.detached` phase with progress feedback before invoking `hv_winvm_create()` on `@MainActor`.
10. **`ios/Sources/HengeVMBridge.mm` (lines 100–105, 362–385) & `ios/Sources/HengeLinuxApp.swift` (lines 100–103 — `suspend.state` Metadata-Only & Missing `beginBackgroundTask`):**

11. **`ios/Sources/SessionView.swift` (lines 599–628 — Synchronous `@Binding` Mutation Inside `updateUIView` & Unconditional `dismantleUIView` Layer Detach):**

## 5. Full-Repository 42-File Deep Audit & Physical-Device Boot Log Findings (Post-Milestone 5.6 / Commit `7628e20`)

A complete 5-batch audit across all 42 repository files plus physical iPhone boot telemetry (`2024.02-2ubuntu0.10` EDK2 UEFI + `ramfb 800x600` + `Blessed 384 MiB @ 0x100b7c000`) identified the root cause of the TianoCore `Start boot option` boot stall and cataloged 28 prioritized remediation items (`P1`–`P3`) for the next engineering pass.

### 5.1 On-Device Boot Log Diagnosis & Telemetry Findings
1. **Verified Working on Physical iPhone Hardware:** TXM dual-mapped JIT (`Blessed 384 MiB @ 0x100b7c000`), vCPU startup, EDK2 ArmVirtQemu UEFI firmware (`2024.02-2ubuntu0.10`), and `ramfb` (`800x600`) initialize cleanly, then UEFI `BdsDxe` stops at `Start boot option` with zero `EFI stub:` or `systemd-boot` output on `ttyAMA0`.
2. **Root Cause #1 — `objcopy` UKI PE/COFF Header Rejection vs. Native `systemd-bootaa64.efi` (`scripts/build_prebuilt_archlinux_arm64.sh:250-305`):**
   - Constructing `EFI/BOOT/BOOTAA64.EFI` by running `objcopy --add-section` on Ubuntu 24.04's `/usr/lib/systemd/boot/efi/linuxaa64.efi.stub` without updating PE/COFF optional header `SizeOfImage`, `SizeOfInitializedData`, and `.reloc` entries produces an EFI binary that strict EDK2 `LoadImage()` can reject with `EFI_LOAD_ERROR` / `EFI_SECURITY_VIOLATION`, dropping silently to the TianoCore menu.
   - **Fix:** Install Arch Linux ARM's native `systemd-bootaa64.efi` (`$MNT_DIR/usr/lib/systemd/boot/efi/systemd-bootaa64.efi`) as `EFI/BOOT/BOOTAA64.EFI` (which natively parses the existing `loader/loader.conf` and `loader/entries/arch.conf` without PE header surgery), falling back to direct `CONFIG_EFI_STUB` `/boot/Image` + `startup.nsh` (`\Image initrd=\initramfs-linux.img ...`).
3. **Root Cause #2 — QEMU `VERIFY_BOOT=1` Device Tree vs. HengeVM ACPI 6.3 Mismatch (`scripts/build_prebuilt_archlinux_arm64.sh:436-438`):**
   - `VERIFY_BOOT=1` invokes `qemu-system-aarch64 -machine virt,gic-version=3` *without* `acpi=on`, testing Device Tree boot in CI whereas `HengeVM` emulates an **ACPI 6.3** motherboard (`-machine virt,gic-version=3,acpi=on`).
   - **Fix:** Pass `-machine virt,gic-version=3,acpi=on` to `qemu-system-aarch64` in `VERIFY_BOOT=1` so CI validates the exact ACPI 6.3 boot path used on iOS.
4. **Immediate UEFI Shell Workaround on Existing Images:**
   - Before rebuilding `archlinux.hvsparse`, tapping **Esc** during the TianoCore splash -> **Boot Manager -> EFI Internal Shell** and executing `fs0:\Image root=UUID=<ROOT_UUID> rw rootwait console=tty0 console=ttyAMA0,115200` bypasses the UKI stub and boots `/Image` directly via Linux's built-in `CONFIG_EFI_STUB`.
5. **Secondary Telemetry Note (`standard ledger` vs. `LEDGER_NO_FOOTPRINT`):**
   - Even when `CS_DEBUGGED=YES` (`cs_debugged=1`) persists after debugger detach, `mach_memory_entry_ownership(..., VM_LEDGER_FLAG_NO_FOOTPRINT)` falls back to standard ledger (`2560 MiB · 2D GOP (standard ledger)`) on iOS 26+ when not actively `P_TRACED` because `VM_LEDGER_FLAG_NO_FOOTPRINT` requires `com.apple.private.memorystatus` when detached. `2,560 MiB` still fits safely within an 8 GB iPhone's Jetsam ceiling.
6. **Root Cause #3 (Resolved in `cf6f1f0`) — `COMMPAGE_TIMEBASE_OFFSET` Clock-Domain Mismatch Freezing EDK2 `ArmTimerDxe` (`scripts/apply_upstream_patches.py`):**
   - Replacing `COMMPAGE_TIMEBASE_OFFSET` (`0xfffffc088ull`) with `hengelinux_negative_counter_offset_ptr()` in `core/translate.c` caused inline guest `MRS CNTVCT_EL0` / `CNTPCT_EL0` instructions to return raw hardware counter ticks (`hardware_CNTVCT_EL0 + 0`), whereas `hv_timer_update()` (`devices/timer.c`) compared `cntv_cval` against `hv_counter()` (`mach_absolute_time() = hardware_CNTVCT_EL0 + *(int64_t *)COMMPAGE_TIMEBASE_OFFSET`). On any iPhone that has slept since boot, `mach_absolute_time()` is billions of ticks smaller than raw `CNTVCT_EL0`, so once EDK2 `ArmTimerDxe` armed `CNTV_CVAL_EL0 = MRS(CNTVCT_EL0) + period` at `BdsDxe` entry (`Start boot option`), the timer interrupt never fired—freezing both `systemd-boot`'s countdown timer and UEFI's timer-driven keyboard polling (`TerminalConInTimerHandler`).
   - **Fix (`cf6f1f0`):** Preserved `COMMPAGE_TIMEBASE_OFFSET` addition in `translate_counter()` before adding `*hengelinux_negative_counter_offset_ptr()`, and patched `core/dispatch.c` to use `hv_counter()` for all `timer_due` / `next_due` comparisons.
7. **Root Cause #4 (Resolved in `40f19cb` & `cf6f1f0`) — UEFI PL011 Serial Keyboard Input & PCIe Slot Alignment (`ios/Sources/HengeVMBridge.mm`, `scripts/build_prebuilt_archlinux_arm64.sh`):**
   - Ubuntu's `AAVMF_CODE.fd` polls PL011 UART (`0x09000000`) rather than xHCI USB during UEFI boot. `HengeVMBridge.mm` (`henge_forward_hid_to_pl011`) now forwards HID keystrokes (ASCII, `Esc`, `Return`, `Tab`, `Backspace`, `Delete`, `F1`–`F4`, `F12`, and arrow VT100 sequences) to `hv_pl011_receive(board->uart, ...)` alongside `hv_winvm_key_hid()`.
   - `scripts/build_prebuilt_archlinux_arm64.sh` configures `systemd-bootaa64.efi` with `timeout 0` and `console-mode keep`, runs `VERIFY_BOOT=1` with `HengeVM`'s exact PCIe slot layout (`00:01.0` `virtio-net-pci`, `00:02.0` `nvme` `WIN11IOS01`), and copies the resulting `verify_vars.fd` (`Boot0000`) into `vars.fd`.
